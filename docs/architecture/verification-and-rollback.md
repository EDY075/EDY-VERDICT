# Verification, manual change and restart

Production rollback and automatic apply are POLICY_BLOCKED. The historical reversible
executor remains compile-time isolated for state/receipt concepts and regression tests;
its concurrent replacement safety is not claimed.

## Fresh verification

Only the original scanner/check family can establish resolution. The available repository
path uses existing edy-inventory lockfile presence/empty-lockfile observations, not expected
text comparison. Plan creation binds original manifest paths and baseline material
fingerprints. Missing manifests cannot be “fixed” merely by disappearing.

A fresh inventory and original-family finding evaluation are bracketed by new inventory
and directory-identity checks. Resolved requires original absence, required checks,
sufficient coverage, stable observed snapshots, no contradictory evidence and no new
material finding. This limited result does not prove vulnerability freedom or system safety.

Missing required checker/provider, insufficient coverage or scan failure is inconclusive.
Cancellation, invalid target and new material finding have explicit non-resolved states.
The final cancellation decision and persistence are serialized against cancel acknowledgement.

## Restart and resume

Plans, guidance, authorization metadata, outcomes and case timeline survive restart.
Pending/running verification becomes interrupted; old authority is consumed and cannot be
replayed. Startup never performs an automatic rescan or target write. The user explicitly
chooses Verify after manual change / Resume verification to obtain new authority.

Tests cover planned, awaiting manual change, verification pending/running, cancelled,
inconclusive, resolved and regression restarts, plus native stop/relaunch during verification.
Cases retain real Level 5 membership and only resolve when all members are resolved.

## Operational limitations

A pending grant whose browser request failed can be safely cleared by application restart,
which makes it explicitly resumable. This is conservative, not silent automatic retry.
Suggestions for unavailable checker families remain manual/unsupported. No automatic
backup, target journal, restoration, file deletion, quarantine or host repair is performed.
